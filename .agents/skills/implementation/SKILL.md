# Implementation

Use this skill when the user asks you to implement an agreed plan or software change. Treat the conversation, plan, and existing project conventions as the source of truth.

## Work clearly

- Account for the user's ADHD: keep updates and summaries brief, show the current step when useful, and avoid unnecessary detail or status chatter.
- Break larger changes into a few manageable steps. Ask only about blockers or unresolved choices that would change the work; continue independent tasks.
- Use the plan's reusable APIs and patterns. Remove code made obsolete when in scope; keep it when compatibility requires it.
- Write readable, self-documenting code with direct control flow. Choose the simplest approach that meets requirements, without skipping needed validation or error handling.
- Add comments only when they clarify non-obvious reasoning; keep them short.
- Inspect relevant project guidance, stay within the agreed scope, and run the project-specific checks.
- Finish with a concise summary of changes, checks, and any remaining work. Explain briefly if compatibility required keeping obsolete code.
